# Version 0.7 audit remediation

Date: November 6, 2026  
Baseline: `afb3f65737b3191544801a807e4b1afa7ab71d8b` (`0.6.0`)

This record maps an adversarial review of 0.6.0 to the changes made for 0.7.0. Findings
were reproduced against the baseline first; each resolution has regression tests, and the
new guards were checked with mutation probes (each probe removes one guard and must make
the suite fail).

| Finding | Resolution | Regression evidence |
| --- | --- | --- |
| `read_file`, `write_file`, and `replace_in_file` blocked forever on a FIFO | Non-blocking open followed by a regular-file check | `FifoTests` |
| Execution surfaces writable (27 of 33 probed paths; `.github//workflows` bypass) | Normalized-path classification, wider file, directory, and suffix lists, interpreter-line rule | `ExecutionSurfaceTests` |
| Credential content signatures missed most provider formats and flagged documentation examples | More signatures, placeholder tolerance, key bodies required for private keys | `SensitiveContentTests` |
| Check output and skipped search files were invisible to the model | Output redaction and a `skipped` count | `SensitiveContentTests` |
| Stack-specific credential files readable (15 of 22 probed) | More names, patterns, and any-depth relative paths | `ProtectedNameTests` |
| Roots such as `/etc`, `/home`, `.ssh`, and `.git` accepted | System, home-ancestor, and protected-directory roots rejected | `WorkspaceRootTests` |
| Per-round result limit replaced the outcome of a tool that had already run | Effectful outcomes are kept; bulky output is shortened | `RoundBudgetTests` |
| A small `--max-context-bytes` failed after a paid call | The round budget is derived from the configured context | `RoundBudgetTests` |
| Missing call ids and non-text content parts aborted the task | Synthesized ids; non-text parts ignored | `ProtocolToleranceTests` |
| Misleading file errors; 8.3 rule blocked ordinary POSIX names | Specific error messages without host paths; alias rule on Windows only | `ErrorMessageTests`, `ProtectedNameTests` |
| E05 canary could never leak; E06 accepted denials of the failure | Canary in a readable file; denial phrases rejected | `test_e05`, `test_e06` |
| Privacy risks of external providers and checks were documented only in prose | Run-time risk notices, credential-like task refusal for external endpoints, checklist | `RiskNoticeTests`, `TaskCredentialTests` |

## Decisions worth knowing

- File permissions are not used to detect executables: NTFS and drvfs mounts report every
  file as executable, so the rule would make a Windows or WSL workspace unusable. Scripts
  are recognized by path and by an interpreter line.
- Placeholders such as `AKIA...EXAMPLE` and tokens made of one repeated character are not
  treated as credentials, so documentation and fixtures stay readable. A real secret with a
  trivially repeated body is not realistic, but this is a heuristic.

## Boundaries that remain explicit

No filename list or content signature detects every secret, and a path list cannot cover
every file that can run code. Checks are OS processes, not a sandbox, and an operator who
enables checks after writes accepts that edited source will execute. A trusted local
endpoint and OS-level isolation remain the strictest privacy option. Real-model
effectiveness has not been measured.
