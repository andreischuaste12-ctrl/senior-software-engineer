## Cross-ecosystem discovery

The submission identified deps.dev, Ecosyste.ms, Repology, and DevDocs as possible
cross-ecosystem discovery services. Aggregators are useful for discovery but are not
a substitute for a registry, maintainer documentation, or a vendor support policy.

## Systems and native development

- C and C++: ISO working groups, cppreference, compiler support tables, Conan, vcpkg.
- Zig, Nim, and D: official language documentation, package registries, and release notes.
- Assembly: architecture-vendor manuals for x86, Arm, and RISC-V.
- WebAssembly and WASI: official specifications, proposals, and Bytecode Alliance material.
- LLVM, GCC, CMake, Meson, and Bazel: maintainer documentation and release notes.

## Application ecosystems

- Python: Python documentation, PyPI JSON API, packaging specifications, and PEPs.
- JavaScript/TypeScript: Node.js, npm, MDN, TC39, and TypeScript documentation.
- Go: specification, module reference, package documentation, and release notes.
- Rust: Rust and Cargo books, docs.rs, crates.io, RFCs, and release notes.
- Java/Kotlin/Scala: OpenJDK, Maven Central, Gradle/Maven, and language documentation.
- .NET: Microsoft Learn, NuGet, runtime repositories, and language proposals.
- PHP, Ruby, Elixir/Erlang, Dart/Flutter, Swift, Objective-C, Haskell, OCaml,
  Clojure, F#, Julia, R, and Lua: official documentation plus their primary registries.

## Platforms and infrastructure

The submission also covered Android, Apple platforms, browsers, React and related
web frameworks, databases, cloud providers, containers, Kubernetes, Terraform,
Ansible, CI systems, security databases, and observability tooling.

For each task, use only sources relevant to the repository. Confirm the target
version and provider. Never assume a catalog entry authorizes network access,
package installation, or transmission of private project information.
